# M6 perception
`input → photo/video frontend → COLMAP → camera/pose/point cloud → Open3D plane extraction → scale evidence → CanonicalWorldModel`.

Install Python dependencies and COLMAP (the `colmap` executable, tested against modern COLMAP 3.x releases). Run `floorplan-ai perceive-photo --input photos --output output` or `floorplan-ai perceive-video --input walk.mp4 --output output`. Outputs include `canonical.json`, `diagnostics.json`, reconstruction camera/pose JSON, PLY points, correspondence evidence, and video frames/trajectory.

COLMAP is the reconstruction backend and Open3D `PointCloud.segment_plane` is the plane segmentation backend. Photo EXIF (dimensions, focal length, make/model, and orientation) is optional camera initialization evidence, not ground truth; where usable it is passed as a COLMAP focal prior and camera provenance records `EXIF+reconstruction`. COLMAP failures produce a degraded canonical model containing captures and image observations but no fabricated poses or geometry. Monocular COLMAP scale is normally `UNKNOWN`: factor 1.0 is only an unscaled coordinate convention, not metric evidence. Ground truth, laser/tape measurements, hard-coded room dimensions, and benchmark data are never used. Video frame timestamps and frame-to-pose/capture provenance are stored in `reconstruction/trajectory.json`, not in the frozen M4 `Pose` schema. Plane candidates are evidence only; M6 does not perform final room/wall/opening structural inference, property stitching, measurements, or drift correction. This document does not claim successful real-media reconstruction in every runtime environment.
